What changed: rotary settings and stateful tasks · 19 October

The learner and sampler now use matching rotary geometry.

Cause
The checkpoint has an old top-level rotary fraction of 0.5, plus per-layer fractions of 0.5 for global attention and 1.0 for sliding attention. Native Transformers normalized the legacy value into both types. vLLM retained the sliding value. Their first sliding-attention outputs diverged before the first MoE block.
Correction
Read the original config independently; restore per-layer dictionaries; remove real legacy instance fields; preserve read-only compatibility properties. Both pretrained and meta construction now give the required 64 global and 128 sliding rotary dimensions. The checkpoint files are unchanged.
Earlier false reassurance
One CPU cache comparison reused a dictionary mutated by config construction. Both test objects therefore used altered settings. The new proof preserves the original dictionary and checks constructed model objects, then all real sampled target tokens.
Stateful tasks
Laguna is the policy LLM. The dataset's small PyTorch reference model is a different object. A submission may now define ModelNew; the verifier copies that reference operation's weights and constructor state, not Laguna's weights. The candidate must still call its CUDA extension.
Checks retained
Fresh correctness trials, strict parameter/buffer matching, separate input tensors, structured outputs and mutation checks. A deliberately wrong computation is rejected. Both benchmark paths disable autograd. Reward weights are unchanged.
Progress since this diagnosis
The resumed sigmoid update passed and saved step 2. Softplus then started automatically. The full 50-task loop and a separate pre/post comparison remain unproven. No model-quality improvement is claimed.

What per-turn RLM credit means

A trajectory can inspect, write, test and submit. GRPO calculates one advantage from its final reward. The same advantage trains each root reply, using the exact prompt that reply saw. REPL observations and child replies are not loss targets.

Ai=Ri−R¯std(R)+10−4
  • The reward mean and standard deviation use four trajectories, not 22 replies.
  • All 18 adjacent root-turn transitions in this run had non-append-only prompts. Joining them into one transcript would train on the wrong context.
  • The native DAPO clipped-PPO loss is normalized by real root target tokens. Zero-credit padding keeps distributed work aligned; it cannot add policy gradient.
  • Prompt and sampled-response IDs come from the inference engine. They are not rebuilt from decoded text.

Learning notes, limits and measured cost
Single policy versus vLLM sleep
This route reuses the training model for generation. It avoids a second resident base and weight synchronization. The explicit CPU move tests memory release between phases; it does not validate vLLM sleep, tensor-parallel inference or adapter-only reload into another engine.
Why move optimizer state?
model.to(...) does not move Muon momentum. The phase helper moves both, checks values bit-for-bit, and verifies that the next real backward and optimizer update work. This is not disk checkpoint save/resume.
Why eight tokens?
Only to bound this hardware test. Minimum and maximum generation lengths are equal. The logged clipped-completion ratio of one is intentional here, not a proposed curriculum setting. No conclusion about reasoning quality or successful CUDA submission follows.
Parallelism still needs work

What failed, what we fixed, and how to read the evidence
Checkpointing settings
TRL enables gradient checkpointing by default. We disabled that flag and used FSDP activation checkpointing instead. Enabling both stops initialization.
Meta RoPE buffers
Accelerate restores each rank's nonpersistent buffers locally. Rank 1's four small RoPE buffers were placeholders with no data. We broadcast their real values before native preparation. A CPU-only reproduction confirms the invalid copy. The first full attempt stalled and was stopped; its original rank exception was not saved, so this attribution is a postmortem inference, not its captured traceback.
Optimizer remapping
The corrected meta-based tiny fixture found a second issue: all meta adapters have storage pointer zero. Accelerate's pointer map can collapse distinct optimizer entries. Giving only those adapters distinct CPU storage fixes the map; full pretrained values still come from rank 0. A CPU reproduction checks all 320 pointers. The GPU step guard now requires exact, unique coverage of the trainable parameters.
SkyRL SDPA patch
The pinned wrapper imports FlashAttention padding helpers eagerly, even for padded SDPA. A recorded patch makes only that import lazy. Calling those helpers still requires real FlashAttention. This was not a FlashAttention execution test or an unmodified upstream checkout.
Meaning of the gradients
Both full-model paths had 160 adapter tensors with nonzero first-step gradients. LoRA B starts at zero, so A gradients initially vanish. Decay can still change A. All 320 tensors changed, but that is not evidence of better CUDA kernels.
Not a framework benchmark
SkyRL used its native strategy under torchrun, not Ray orchestration. TRL used its full trainer. Their auxiliary-loss handling and checkpointing differ. Similar short-probe times do not establish equal objectives or production throughput.
Still untested
vLLM generation and phase sharing, adapter reload, real RLM trajectories, CUDA verification, compact checkpoint restart, realistic-context memory and quality. Both resident BF16 model copies still do not fit together. The two pins also require different vLLM versions; a shared trainer-check environment does not prove shared inference dependencies.

How to compare actual cost

Cost is allocated resources multiplied by time to a useful result, including startup and failed attempts. Under equal per-GPU pricing, two GPUs beat three only if they take less than 1.5 times as long. CPU/RAM charges, provider credits and storage change this threshold.

How the guards work
  1. Compile with CUDA devices hidden, without blocking inference.
  2. Check the reference against the measured profile list. Reject unsupported contracts and common direct-allocation or allocator-control APIs from the overlap path.
  3. Allow one intermediate verifier at a time. Share its admission lock with inference, while excluding final scoring and weight reloads.
  4. Require an A100 and free memory of at least the allocator cap plus 2 GiB. Cap PyTorch allocations at 512 MiB for vector addition or 4 GiB for softplus.
  5. If memory is insufficient or a capped allocation fails, release the worker and retry exclusively using the original remaining timeout. Do not consume another agent feedback call.

The allocator cap is not a hard GPU partition. Raw native CUDA allocations can bypass it; source exclusions are conservative heuristics. Keep the measured profile list narrow. Scheduling does not change reward calculation.

2. Keep the current decisions clear

Reward: correctness and speed both matter
  • Valid source earns partial credit.
  • A compiled extension earns more credit.
  • A correct result earns correctness credit and a speed bonus.
  • Intermediate feedback gives information, not reward. Only the final submission is scored.

For a valid, compiled, correct submission:

r=0.7+0.1×clamp(speedup,0,3)

Speedup is reference time divided by kernel time. A value below 1 means the kernel is slower.

Filter: reject identical total rewards. Keep all-correct groups if their speed rewards differ. Timing noise can affect admission.

Superseded: the temporary quality-only reward and quality-diversity gate are not the current policy.

Subcall limits and evaluation control
  • Training permits up to two optional child requests per trajectory. Batched calls share this budget.
  • Each child has a 2,048-token prompt cap, plus its fixed system message, and a 2,048-token output cap. Total child output is bounded at 4,096 tokens per trajectory.
  • Each request has a 90-second deadline and no retry. A failed request consumes one call allowance.
  • The child has no tools or recursion. It can return focused text with a code fragment; the root stores the response in the REPL and remains responsible for the complete kernel.
  • Only the final kernel receives correctness-and-speed reward. There is no delegation bonus.
  • Use the harness default, subcalls disabled, for the no-delegation evaluation control. The frozen wiring probe still forces one call and is not a quality comparison.

4. Learn the training loop

  1. Select a task. Put the reference in the Python REPL.
  2. Generate attempts. The model writes code and receives REPL output.
  3. Test a candidate. cuda_feedback(source) returns compiler and correctness feedback.
  4. Submit. The model sets the answer content and ready flag.
  5. Score. The verifier checks the final source and measures speed.
  6. Update. Prime compares rewards, filters groups, and updates LoRA parameters.
Turn, trajectory, group, batch, and step
Turn
One model response and its environment interaction.
Trajectory
One complete attempt, with one or more turns.
Group
Attempts at the same task. Training group size: 4.
Training batch
Accepted trajectories for an update. Configured size: 4.
Micro-batch
A smaller packed token unit. The trainer accumulates gradients across these units.
Optimizer step
An update to trainable parameters. It is not a REPL turn.
Async execution and GPU roles
  • One A100 runs vLLM inference.
  • Two A100s jointly train Laguna with expert parallelism.
  • Prime overlaps generation and training by default.
  • Group-relative scoring still needs the group results.
  • The inherited maximum policy-version lag is 8. This is a limit, not a constant delay.

Modal provides compute and storage. Prime coordinates training. Our environment defines interaction and reward.

GRPO intuition and pseudocode

Compare each attempt with other attempts on the same task. In the mean-centered form:

Ai=ri−r¯
  • Positive advantage favors the sampled actions.
  • Negative advantage discourages them.
  • Identical rewards give no relative reward signal.
repeat until the step or time limit:
    sample a group of trajectories
    verify each final submission
    compute total rewards, including speed
    if all total rewards are identical:
        reject the group
        continue within the time budget
    pack accepted trajectories into micro-batches
    accumulate gradients and update LoRA parameters
    synchronize inference weights
    save a checkpoint when scheduled

This is a conceptual loop. Prime overlaps generation and training and applies its configured loss corrections.

Checkpoint versus inference weight update
Checkpoint
Model state, optimizer, scheduler, and progress. Used to resume training.
Weight update
Transfers the current policy to inference. Not a substitute for a checkpoint.
Retention
Limits saved checkpoint count. It does not eliminate write cost or limit all other artifacts.

Research reading list and future experiments
  • Liu et al., On Effectiveness and Efficiency of Agentic Tool-calling and RL Training (ICML 2026): reports that prompt, seed, history, and turn formatting can change results. Low-cost lesson: freeze and log them. It proposes skipping prompts after consecutive all-correct groups and down-sampling the lowest/highest-reward rollouts to reduce update cost. Their reported wall-clock speedups are 1.7× and 2.6× in their single-/multi-turn settings. For us, do not skip merely because all kernels are correct: speed is also rewarded. Consider filtering only repeatedly saturated, same-reward groups; down-sampling waits until we measure update time.
  • Lee et al., Rewarding How Models Think Pedagogically (arXiv v1): uses domain-specific prompts and an LLM-judged thought reward for tutoring. Transfer the domain-specific prompt idea; do not add thought judges to CUDA RL. Their setup adds three GPT-4o-mini judge calls and uses four GPUs, so it is not a low-cost fit.
